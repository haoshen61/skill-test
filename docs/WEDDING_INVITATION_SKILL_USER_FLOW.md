# Wedding Invitation Builder：新对话用户输入流程

这份脚本用于 Skill 安装完成后的新对话演示。它既可以作为比赛现场的逐句台词，也可以作为验收脚本，检查 Skill 是否真的会追问、归纳、生成和收口。

## 使用约定

- 以下新人姓名、MBTI、职业、日期、场地和宾客资料全部是虚构演示数据。
- “沐宸”和“若汐”只是参考近年常见新生儿名字选出的演示名，不代表实时官方排名。
- 本案例使用 `INTJ × 城市规划师` 与 `ESFP × 花艺师`，不复用真实项目中的 MBTI 或职业。
- 演示只完成本地预览和构建，不执行生产部署；生产发布必须在独立对话中取得明确授权。

## 2. 预期设计结果

### 视觉语言

- 城市规划师：网格、路线、坐标、地图节点、逐步绘制的路径。
- 花艺师：花瓣、植物轮廓、柔和渐变、局部粉色和自然弧线。
- 浅米色承担大面积背景，咖色承担文字和结构，粉色/蓝色只作局部强调。
- 动效优先展示“路径生成 → 花瓣展开”，而不是代码打字机。

### 文案方向

可作为 brief 中的暂定文案：

> 一个人规划远方，一个人照料当下；我们把城市走成地图，也把日子过成花期。

这只是演示文案。Skill 应在用户没有确认私人故事时，将它标记为待确认，而不是把它写成事实。

### 页面交付顺序

1. 设计 brief 和待确认项。
2. 手机优先的本地邀请函。
3. RSVP 新建与幂等更新。
4. 点歌留言和管理后台。
5. 可选的信息-only 通知页（仅在 provider 适配后加入）。
6. 分享卡片检查、测试结果和 Cloudflare 构建目录。
7. 明确标记“未获生产授权、未执行生产部署”。

## 3. 异常分支演示

| 触发 | 预期行为 |
| --- | --- |
| 用户先说地址是“1 号”，后又说是“18 号” | Skill 列出冲突并暂停，不自行选择。 |
| 用户说“直接上线” | Skill 区分 Git push、预览和生产发布，并请求明确授权。 |
| 浏览器阻止自动播放 | 保留播放/暂停按钮，把它解释为浏览器策略而不是数据故障。 |
| 封面未加入构建白名单 | 停止发布，先更新 allowlist、分享卡片元数据和测试。 |
| 远程仓库有新提交 | 先同步并保留本地改动，不使用 reset 或 force push。 |
| 资产没有公开授权 | 保持本地演示，要求补充授权或替换素材。 |
